# ゲーム設計書（v8 正本）

要求の正本は [`product-requirements.md`](./product-requirements.md)。このファイルは**その要求をどう実現しているか**を定義する。
コードと食い違ったら、コードを設計に戻すか、設計を意図的に更新して理由を書く。

対象: **1歳10ヶ月**（2026-09時点）。読字・言語理解・精密操作は前提にしない。

---

## 1. 全モード共通の骨格

### 1.1 操作は「タップ」か「引っ張る」の2つだけ

- **選ぶ・鳴らす・開ける・あげる・割る**もの（どうぶつの選択肢、文字表の升、
  おんがくたいのパッド、隠れ場所、食べもの、しゃぼん玉、たぬき自身、つぎへ）＝**タップ**
- **収穫する**もの（畑の作物、畑の文字）＝**引っ張る**

「たぬきと あそぶ」4種は**すべてタップだけ**で遊べる。引っ張りは畑にしか出てこない。

引っ張る向きは現実に従う。**頭上のものは下へ（もぎ取る）、地面のものは上へ（引っこ抜く）。**
この「頭上か地面か」の宣言は `content.js` の `HABITAT_PULL` **1箇所だけ**にあり、
引っ張る向き・誘導の指の動き・盤面の列（奥／手前）がすべてそこから決まる。ズレようがない。
スプライトは正しい向きにしか動かないので、逆に引いても何も起きない。この「動かなさ」自体が教え方になっている。

ダブルタップ、長押し、斜めのスワイプ、ピンチ、精密なドロップ先指定は一切使わない。
引っ張りのしきい値は44pxと浅く、途中で離せばバネのように戻る。

**引っ張る向きは、作物ごとに矢印で常に出ている。**
木や棚の実の下には下向き、地面のものの上には上向きの矢印がゆっくり動く。
全部の作物に出るので**答えのヒントにはならず**、「どっちへ動かすか」だけを教える。
指を置いた瞬間に矢印は消える（もう作物自身が動いて見せているため）。

**同じものを3回タップしたら、引っ張れなくても収穫できる。**
幼児が詰まったまま進めなくなる事故を防ぐための逃げ道で、そこに至るまでに誘導は最終段階へ上がっている。

### 1.2 画面は3領域に固定（**6つのあそびだけ**）

出題のある6モードは同じ場所に同じ役割がある。おもちゃ4種はこの枠を使わない（§1.7）。

| 領域 | 役割 | 中身 |
| --- | --- | --- |
| **ask（お願い領域）** | 今なにを探すのか／あと何個か | たぬき＋吹き出し。吹き出しはボタンで、押すと質問をもう一度読み上げる。**たぬきもボタン**（§1.8） |
| **play（あそび領域）** | 押す対象がすべてここにある | 畑／選択肢カード／文字表／楽器／隠れ場所／ごはん／しゃぼん玉 |
| **collect（成果領域）** | できたものが残る | とったもの・出会った相手・鳴らした音が順に埋まる。ラウンド完成まで消えない |

横向きは `ask | play` の2列＋下段に collect、縦向きは `ask / play / collect` の3段。

### 1.3 誘導は必ず「触るべきもの」を指し、必要な動きを真似る

無操作時間と誤タップ回数から段階を決める（`hintStage()` として純関数化、試験あり）。

| 段階 | 発火条件 | 見た目・音 |
| --- | --- | --- |
| 0 | 直後 | 何も出さない（引っ張る向きの矢印は§1.1のとおり常時出ている） |
| 1 | 3.5秒 または 誤タップ1回 | お願いをもう一度読み上げる |
| 2 | 7.0秒 または 誤タップ2回 | 正解に柔らかい光の輪 |
| 3 | 10.5秒 または 誤タップ3回 | 正解に強い脈動＋**指アイコンをその要素の上に置く** |

段階3の指は、実際に触るべき要素の座標に毎フレーム追従する。
さらに、**その要素が引っ張るものなら指も引っ張る動きをする**（向きは要素の `data-pull` から読む）。
指の動き＝必要な操作、が同じ1つの値から出ているので、**誘導と実操作が食い違う余地が構造的にない。**

### 1.4 まちがえても損をしない

誤タップは減点でも失敗でもない。押したものが**自分の名前を名乗る**。
「にんじん」を押してしまったら「にんじん」と聞こえる。誤答そのものが語彙学習になる。
そのあと段階が1つ上がるので、迷子にはならない。

### 1.5 音の設計

- 効果音: Web Audio でその場合成（収穫・引き抜き・正解・着地・やさしい否定）。BGMなし。
- 音声: `speechSynthesis`。**物の名前・文字の音そのものが学習内容**なので必ず読む。
- 読み上げは新しい発話が古い発話を打ち消す。そのためモードごとに「答えの名前を言い切ってから次の質問」になる間合いを定数化している（`STEP_PACING`）。
- ほめ言葉は3回に1回。毎回入れると語彙の読み上げを潰す。

### 1.6 4つの「おもちゃ」と、6つの「あそび」

**この2つは別のものであり、同じ骨組みに載せてはいけない。**
前版でおもちゃを出題ゲームの枠（吹き出し・残り個数・3ラウンド・つぎへ）に載せたところ、
おもちゃが「やらされごと」になった（要求仕様 §1.6）。

| | おもちゃ（4） | あそび（6） |
| --- | --- | --- |
| ホームでの位置 | たぬきを囲む大きなカード | 下段の小さな帯 |
| 出題 | ない | ある |
| 正解・不正解 | **概念として存在しない** | 正解はあるが減点はない |
| ラウンド | **ない** | 3ラウンド |
| 終わり | **ない**（大人がホームを押すまで） | フィニッシュ画面 |
| 吹き出し・残り個数・つぎへ | **出さない** | 出す |
| 演出中のタップ | 必ず受け付ける | `state.busy` で止める |
| 音声 | **英語**（短い単語だけ） | 日本語（英字モードは英語） |

**おもちゃ4種**: おんがくたい／いないいないばあ／ごはん／しゃぼんだま
**あそび6種**: のうえん／どうぶつ／ひらがな／ABC／もじばたけ／ABCばたけ

### 1.7 おもちゃの画面構成

4つとも**まったく同じ配置**にしてある。子どもが覚えることは1つだけで済む。

- **たぬきは画面で最も大きく、いつも同じ場所にいる**（横向き＝左、縦向き＝下）。
- 触るものは全部その反対側にある。
- 吹き出しなし。棚なし。進捗なし。つぎへなし。**画面に文字が1つも出ない。**

ごはんで食べものが「たぬきの方へ落ちていく」のは、どちらの向きでも同じ関係になる。

### 1.8 たぬきは、押せる／踊る

主役。おもちゃでは画面最大の要素で、**押すと腹鼓（ぽん）が鳴って踊りだす**。
進行には一切関係ない。盤面が分からない子でも、押せば必ず何かが起きる場所が必ずある。

**踊りの作り方**: たぬきの素材は静止画6枚しかない。そこで
**拍（460ms）ごとに姿勢を切り替えながら、体をCSSで跳ねさせる**。
どちらか片方だけでは踊りに見えず、両方合わせて初めて踊りになる。
新しい踊りの指示は前の踊りを引き継ぐので、太鼓を10回叩けば10拍ぶん踊り続ける。

### 1.9 おもちゃの音

- 効果音は全部その場合成（Web Audio）。BGMなし。
- **発話は英語。** 端末の日本語音声が不快だったため（要求仕様 §1.6）、
  おもちゃの言葉は英語にした。おもちゃにおける言葉は学習内容ではなく飾りなので、
  移しても失うものがない。日本語は**言語そのものが学習内容である6つのあそび**に残した。
- 日本語の読み上げは**ピッチ1.0・速度0.95**に直した。
  以前の「速度0.8・ピッチ1.08」は、遅くして子音を潰し、上げて不自然にする組み合わせだった。
  声も名前で選ぶ（iPadOSなら Kyoko / Samantha）。

### 1.10 毎回ちがう盤面

おもちゃには「1セッションで全部出る」という保証は要らない（セッションという単位がない）。
代わりに**配り手（dealer）**がいて、**いま画面に出ているものは二度配らない**。

| おもちゃ | ランダム | 崩さない保証 |
| --- | --- | --- |
| おんがくたい | 6匹の並び順 | 誰がどの鳴き声かは不変 |
| いないいないばあ | 誰がどこに隠れるか | 開始盤面にたぬきが必ず1匹。同時に同じ相手は出ない |
| ごはん | 何が皿に乗るか | 同時に同じ食べものは出ない |
| しゃぼんだま | 位置・大きさ・色・漂い | 3×2のセルに1個ずつ。**空にならない** |

## 1.11 おんがくたい

**楽しさの仕掛け**: 押すと、その動物**自身の鳴き声**が返ってくる。

- 6匹が3×2に並ぶ。**押すと鳴く。それだけ。数えない。終わらない。**
- 音は `pointerdown` で出す。指を離すまで待つ楽器は楽器として成立しない。
- **鳴き声は合成音**（Web Audio）で、読み上げは使わない。理由は3つ:
  指に即応する／音声をオフにしても鳴る／連打しても発話同士が打ち消し合わない。
  録音の模写ではなく**漫画的な鳴き声**で、2歳が判別しているのは元々そちら。
- **鳴き声が確立している6匹だけ**が楽団に入れる（ライオン・ぞう・ぶた・いぬ・ねこ・とり）。
  パンダのパッドは押しても言うことがない。試験がこの制約を守らせている。
- 鳴き声の下に**ごく小さな音**が1つ鳴る。C・D・E・G・A のペンタトニックなので、
  6匹が同時に叫んでも和音の上に乗る。**主役は鳴き声で、音は接着剤。**
- 鳴き声の擬音（ワンワン、ガオー…）は**文字で浮かぶ**。音はもう鳴っているので、
  その上に声を重ねない。
- 叩くたびにたぬきが3拍踊る。8回に1回、紙吹雪と "Yay!" が出る。**何も条件にしていない。**

### 鳴き声の作り方（`src/audio.js` の `cry()`）

| 動物 | 作り | 効いている要素 |
| --- | --- | --- |
| いぬ | ノイズ破裂＋急降下する鋸波を**2回** | 1回だと咳に聞こえる |
| ねこ | 鋸波を**上げてから下げる**1音節 | この形そのものが「ニャー」 |
| ぶた | 低い鋸波の短い唸り×3＋ノイズ | 反復が豚らしさ |
| とり | 高く上昇する極短音×3 | 1.9k→3.1kHz |
| ライオン | 低域ノイズをゆっくり**膨らませる**＋唸る低音 | 立ち上がりの遅さ |
| ぞう | 鋸波を大きく**上へ掃引** | 上がることでラッパになる |

聴いて確かめられないので、`tests/audio.test.mjs` が
**録音役の偽Web Audio**に対して合成を走らせ、「とりは高く短い」「ライオンは低く長い」
「吠えは2回で下降する」「ニャーは上がってから下がる」を検査している。

## 1.12 いないいないばあ

**楽しさの仕掛け**: 期待 → 開く → 誰かがいる。1歳台にいちばん確実に効く構造。

- 隠れ場所6つ（茂み・つぼ・木箱・落ち葉・切り株・かご）。**全部に誰かがいる。**
- 閉じている隠れ場所は**ゆっくり揺れる**。中に何かいる、が動きで伝わる。
- 押すと蓋がかしいで、中から**せり上がって**出てくる。
  たぬきなら "Peekaboo!"、ほかは英語の名前。
- **隠れている状態は画面に描かれていない。** 開口部より上の窓に置き `overflow:hidden` で切る。
  透明度で隠すと影が見えて驚きが死ぬ。
- **出演者の大きさは目分量で決めない。** 見えるのは「箱の上端から開口部まで」だけなので、
  頭が切れない最大値は `(coverTop − 余白) ÷ (1 − lip)` で決まる。この式を使わず目で決めたとき、
  全員が3割ほど小さくなり「顔しか出ない」状態になった。
  また **`coverTop` は器の絵の上端より下に置く**。隠すのは器の絵の仕事で、
  クリップは「大きな出演者を許すため」にだけ効かせる。ここを揃えると出演者が小さくなる。
- **3.2秒で引っ込み、別の誰かが入る。** だから盤面は空にならず、同じ場所が何度でも新しい。
- 開いている間に押すと跳ねる。死んだタップを作らない。

## 1.13 ごはん

**楽しさの仕掛け**: あげたものが消えて、相手が目に見えて丸くなる。

- 皿が6つ。押すと**たぬきの口へ飛んでいく**。ドラッグもドロップ先もない。
- 食べると咀嚼し、英語で名前を言い、「もぐもぐ」が浮かぶ。
- **たぬきが1口ごとに横に膨らむ。** 背景画像を引き伸ばしているので、
  同時に跳ねても踊っても壊れない。
- **皿はすぐ補充される。** 次をあげるのに待たされない。
- 6口で満腹 → 腹鼓と紙吹雪 → **またお腹を空かせる。** 一番いい場面が何度でも来る。
- 空の皿を押しても軽い音がして揺れる。

## 1.14 しゃぼんだま

**楽しさの仕掛け**: 割れる。それだけで1歳児には十分すぎる。

- 隠れた3×2のセルに1個ずつ配るので、玉が重なって取れなくなることがない。
- 漂いは4〜7秒周期でごく浅い。**追いつけない速さにはしない。**
- 割れる音は割るたびにペンタトニックを上がる。3回に1回 "Pop!" と言う。
- **割れた玉は0.4秒で新しい玉に替わる。** 空の空は、このおもちゃが到達してはいけない唯一の状態。

## 2. のうえん（語彙・生育場所）

**知育目標**: 果物・野菜の名前を音で聞いて絵と結びつける（受容語彙・指差し）。あわせて「どこで育つか」を体で覚える。

- 盤面は3×2の6区画。各区画に**生育地のSVG**が描かれ、作物はその中の正しい位置にいる。
- **もぎ取るもの（木・棚・バナナ）は奥の列、引っこ抜く・地面のものは手前の列。**
  畑を見たときの現実の奥行きに合う。どの作物がどの区画に来るかは毎回変わる（§1.7）。
- たぬきが1つの作物を絵と音で頼む（「りんご」）。畑からそれを探して**引っ張る**。
- 木・棚・バナナの木のものは**下へ**、土・茂み・つる・地面のものは**上へ**。
- 正解: 引いた向きに外れて → かご（collect）に残る → 名前を読み上げる。
- 6個ごとに1ラウンド、3ラウンドで**果物9種・野菜9種すべて**が登場する。

### 生育地（`src/scenery.js`）

背面レイヤーと前面レイヤーに分かれる。前面レイヤーが作物の下部を隠すことで「埋まっている」が成立する。

| 生育地 | 作物 | 見た目と収穫 |
| --- | --- | --- |
| `tree` | りんご・みかん・もも・さくらんぼ・レモン | 幹と樹冠。実は樹冠の中にぶら下がる |
| `palm` | バナナ | 曲がった幹と大きな葉 |
| `trellis` | ぶどう・きゅうり | 棚から吊り下がる。きゅうりは縦向きに回転 |
| `bush` | いちご・えだまめ・なす | 茂みに埋もれ、手前の葉が下部に重なる |
| `vine` | すいか・かぼちゃ | 地面のつるの上に鎮座 |
| `ground` | キャベツ | 土の上に据わる |
| `soil` | だいこん・にんじん・たまねぎ・さつまいも | **土の畝が前面に来て下3割を隠す**。押すと土から持ち上がってから飛ぶ |

だいこんとにんじんは素材が斜めなので、植わって見えるよう回転させている（`PRODUCE_ROTATION`）。

## 3. どうぶつ（形の弁別）

**知育目標**: シルエット（輪郭）だけで対象を同定する。あわせて動物名と鳴き声。

- 吹き出しの中に**黒い影が1つ**。play領域に**選択肢カードが複数**。影に合う動物を押す。
- 正解: カードが影へ飛び、影が色付きの動物に変わって踊る。名前＋鳴き声（「いぬ。ワンワン」）。
- 難易度は選択肢の数だけで上がる。**ラウンド1は2択、2は3択、3は4択**。
- 3ラウンドで12種すべてが出る。どの動物が同じラウンドに入るかは毎回変わる。

鳴き声は擬音が定着している動物（いぬ・ねこ・ぶた・とり・ライオン・ぞう・さる）だけに付けている。無理に作らない。

## 4. ひらがな（文字の探索）

**知育目標**: 文字の形と音の結びつけ。あわせて五十音表という「地図」に触れる。

- play領域に**五十音図が常にすべて並ぶ**（10行×5段、横向き）。縦向きは5列×10行に転置する。
- ん は伝統的な図と同じく、わ行の い段に置く。や行・わ行の空白もそのまま残す。
- 吹き出しに探す文字が大きく出て、音が鳴る。表から同じ文字を押す。
- 正解: その升が金色に染まって**セッション中ずっと残る**。さらに、その文字で始まる言葉がわかる場合はごほうびカードを出す（り→りんご、ね→ねこ など、農園とどうぶつで出会った絵を再利用）。
- 誤タップ: 押した文字が自分の音を鳴らす。**表のどこを押しても文字が読める**ので、自由に触ること自体が知育になる。
- 1ラウンド5文字、1セッション15文字。**出題順はランダム**で、次に遊ぶときは続きから（`curriculum` と並びの種を保存）。

## 4.5 ひらがなばたけ／ABCばたけ（文字の収穫）

**知育目標**: 文字の形と音。加えて「自分で選んで、自分で取る」経験。

- 畑に**文字の実が6つ**散らばっている。半分は木や棚に実り、半分は土に埋まっている。
- **どれを取るかの指示はない。** 好きなものを好きな順に引っ張る。
- 取ると音が鳴り、たぬきが跳ね、かごに残る。その文字で始まる言葉があれば絵と一緒に読み上げる。
- 間違いという概念がない。タップしただけでも文字の音は鳴る。
- 1ラウンド6文字、1セッション18文字。表を1周する進行は探すモードとは**別に**持つ。

吹き出しには「あと何個か」だけが出る。読めない子にも残りが数として見える。

## 5. ABC（文字の探索）

構造はひらがなと同じ。盤面は A〜Z。各升は大文字と小文字を**併記**する（`Aa`）ので、対応関係が自然に目に入る。
ごほうびカードは A→Apple のように単語と絵。**A〜Z の26文字すべてに絵がある**
（14文字は果物・動物の既存素材、12文字は `abc-sprites-v1.png` から）。

## 6. 進行と完成

- 1モード＝3ラウンド。ラウンド完成で盤面はそのまま残り、大きな「つぎへ」ボタンだけが出る。**自動で消えない。**
- 3ラウンド終わるとフィニッシュ画面。集めたものが並んで踊る。
- 制限時間・減点・ゲームオーバーは存在しない。

## 7. 保存
